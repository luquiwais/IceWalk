## Librerías, por pedido posterior de Eitan

Se detuvo la expansión del solver propio para comparar Motion, React Spring, GSAP/MorphSVG y Flubber con documentación y paquetes actuales. Motion soporta morph de paths compatibles; para topologías distintas puede combinarse con Flubber. Las cápsulas y rectángulos redondeados actuales no necesitan esa segunda dependencia.

Decisión: importar solo el generador `spring` de Motion 14.12.0 (MIT), no montar un `motion.div layout` sobre la ventana completa. Probe Bun browser/minify: 4482 bytes minificados, 2150 bytes gzip; la combinación de API híbrida/valores/efectos/scheduler dio 28820 bytes gzip en el mismo método. Son medidas de un probe, no del delta final del bundle Next.

Esto permite sustituir la física propia manteniendo WAAPI sobre pinturas separadas. Los tipos públicos ofrecen `next(t_ms)`, velocidad y retarget; `next` reutiliza un objeto mutable, por lo que se copian valores. Con física se muestrea hasta `done` real y se fijan umbrales de reposo subpixel. No usar `duration + bounce` para un retarget con velocidad: esa variante inicia desde reposo. Integración y verificación final pendientes al registrar esta decisión.
