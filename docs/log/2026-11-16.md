## Deploy de la evaluación y la API que se caía (tarde, Guido)

- **Web:** `icewalk.vercel.app` estaba con una versión anterior a la entrega. Se redesplegó desde el tag `submission-2026-11-15` más tres arreglos de la web (rama `deploy/submission-hotfix`), sin los commits posteriores al cierre.
- **API dormida:** el keep-alive que había era un workflow de GitHub Actions de otro repo (QuickShare): nunca le pegó a esta API y fallaba siempre (secreto vacío); además GitHub lo corría cada 4-7 h. Ahora un job de cron-job.org (cuenta de Guido) pide `/health` cada 5 min.
- **Mover el hábitat fallaba** ("could not place the habitat there" o "needs the planner API"). Tres causas, corregidas en la web:
  - `{ timeoutMs: PLAN_TIMEOUT_MS, ...options }`: la sesión pasa `timeoutMs: undefined`, que pisaba el valor largo; los planes cortaban a los 8 s y en Render tardan ~15 s. Ahora 60 s, y un timeout o una falla de red se informan como tales.
  - El canal entre ventanas (`icewalk-eva`) es uno para todo el navegador: una pestaña cuya carga falló pasaba su plan mock a cada pestaña nueva, que al adoptarlo cancelaba su pedido a la API. Con la API configurada, ya no se adopta un mock.
- **La API se reiniciaba (502, `x-render-routing: no-deploy`) al mover el hábitat:** `TraverseMap` guardaba hasta 33 campos de Dijkstra (~290 MB) y el plan gratis de Render tiene 512 MB. Medido local: 314 → 427 → 445 → 506 MB con cuatro hábitats. Ahora LRU de 16 campos en float32: estable en ~314 MB. **Falta redesplegar la API en Render** (cuenta de Luqui), desde `deploy/submission-hotfix` o desde `main` después del PR.
- Con tres planes en paralelo, Render gratis tarda 85-90 s cada uno: con varios jurados a la vez la API sigue siendo lenta. Pasar la API a Hugging Face Spaces (gratis, 2 vCPU y 16 GB) lo resolvería.
